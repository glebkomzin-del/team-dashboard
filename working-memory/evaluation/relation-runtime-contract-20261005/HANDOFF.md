## Runtime rule

`canonical_worker.py` passes the actual job ID, source ID, exact document body hash and expected source revision. For each **new commitment candidate only**, `relation_runtime.candidates()` binds those values, observation index, original span IDs and the entire post-gate candidate into its candidate ID. Existing task updates and historical work are outside this stage. The extra `compact-relations` call uses the existing `DurableCalls` ledger, request/content hash, one reservation, one received response and no semantic retry (`attempts=1`). An unknown provider outcome remains paused by existing handling and is never silently resent. The strict schema accepts only candidate ID, relation enum and original-ID arrays. The model's relation is an untrusted proposal, **not** a positive independent withdrawal proof.

Malformed, missing, null, unknown-ID, stale candidate or incomplete response makes **all new candidates** pending review; known `replaced`, `expressly_withdrawn` or `unclear` makes **only the affected new candidate** pending review. This sets `required_review=true`, retains original owner/condition/due/work-gate fields, adds exact original spans, and leaves historical work untouched. `memory.apply()` stores the observation, creates no Work Event for it, and can still apply the source and unaffected observations. `none`, `confirmed` and `independent` do not change the existing gate result. Their semantic truth has not been independently proved. No automatic withdrawal or historical cancellation is implemented.

The post-gate final observations are the sole input to `future_summary.from_final_proposal`; a pending relation is rendered as an explicit open relationship with its original passages. The extraction call's preliminary `meeting_summary` is replaced before archive indexing; the canonical worker stores the returned final summary instead of re-reading the extraction response. This is a deterministic conservative rendering, **not** a human-quality summary acceptance. Large final renderings can fail closed; one real qualification and full package acceptance remain necessary.

## Decision required before any release

The core open risk is a **false `none`** or false `confirmed` relation: the source-only model can miss a real replacement and leave the existing gate's work creation in place. Original-ID membership and chronology are necessary provenance, not semantic entailment. There is no independent generic positive relation oracle in the current unstructured transcript; the prior fixed A/B/C IDs cannot serve as runtime truth and a second model would not prove it. The conservative review path handles *detected* or invalid relations but cannot prove complete detection. An independently reviewed, finite real qualification on a freshly bound job/ledger context must test this, and the Lead must decide whether the residual false-negative risk meets the user's product goal. No all-59 manual review policy or technical queue stop was introduced.
